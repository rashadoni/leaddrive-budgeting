# План работ по UX/UI — «навигация для нетехнического пользователя»

Источник: живой аудит прода (`http://46.225.60.142`, вход `admin@fo.az`, обход 14 экранов desktop+mobile через Playwright, 2026-06-30).
Цель: человек, далёкий от техники, должен спокойно ориентироваться и доходить до результата.

Приоритеты: **P0** — сломано на проде; **P1** — путает/отпугивает новичка; **P2** — доступность и полировка.
Объём: **S** ≤ полдня, **M** ≈ 1 день, **L** ≈ 2–4 дня.

Процесс на каждую задачу (из CLAUDE.md): `npx tsc --noEmit` + `npx vitest run` перед коммитом; один коммит на задачу с обновлением `docs/ROADMAP.md` + changelog; push в `origin main`. **Любая правка вёрстки** (`src/features/terminal/components/*`, `*.module.css`, `globals.css`, `tailwind.config.ts`, сайдбар/layout) → визуальный гейт `npm run test:e2e -- visual-baseline`; при намеренном изменении — регенерация baseline + токен `BASELINE UPDATE: <reason>` в коммите.

## Волна P0 — критичные баги прода (цель: 1 день, выкатить сразу)

### P0-1. `/guide` падает с 500 — починить главный обучающий экран  · **S**
- **Проблема:** «User Guide» в меню → чёрный экран «Something went wrong». Новичок идёт учиться и попадает на краш.
- **Причина:** `readFile(process.cwd()/docs/USER_GUIDE.<lang>.md)` без try/catch; Docker standalone-образ не копирует `docs/`.
- **Где:** `Dockerfile` (runtime-стадия, рядом со строкой 69), `src/app/(dashboard)/guide/page.tsx`.
- **Сделать:** (1) `COPY --from=build --chown=nextjs:nodejs /app/docs ./docs` в runtime-стадию; (2) обернуть чтение .md в try/catch с дружелюбным fallback («Гайд временно недоступен»), а не 500.
- **Готово когда:** `curl -s -o /dev/null -w "%{http_code}" http://<prod>/guide` → 200 на en/ru/az; при отсутствии файла — мягкое сообщение, не краш.

### P0-2. Пункт меню «Alerts» ведёт в 404  · **S**
- **Проблема:** сайдбар → `/budgeting/alerts`, страницы нет (есть только `/budgeting/alerts/history`). Клик = тупик.
- **Где:** `src/components/sidebar.tsx:73`.
- **Сделать:** href → `/budgeting/alerts/history` (или добавить `src/app/(dashboard)/budgeting/alerts/page.tsx` с `redirect("/budgeting/alerts/history")`).
- **Готово когда:** клик «Alerts» открывает страницу алертов, не 404. (Правка сайдбара → визуальный гейт.)

### P0-3. Нет favicon / иконки приложения / PWA-манифеста  · **S**
- **Проблема:** пустая иконка вкладки + 404 `/favicon.ico` в консоли на каждой странице.
- **Где:** `src/app/` (Next metadata API), `public/`.
- **Сделать:** добавить `src/app/icon.svg` + `favicon.ico` + `apple-icon.png` + `manifest.webmanifest` (или `metadata.icons`/`manifest` в root layout). Использовать бренд-«B».
- **Готово когда:** иконка во вкладке видна; `/favicon.ico` → 200; 404 в консоли исчез.

## Волна P1 — доверие и язык (цель: 2–3 дня)

### P1-1. Включить HTTPS на проде  · **M** (инфра, возможно нужен IT PASHA)
- **Проблема:** прод на голом HTTP → браузер показывает «Not secure» на финансовом приложении.
- **Где:** `deploy/nginx/budgetpro.conf` (HTTPS-блок и `return 301` закомментированы), `deploy/README.md §3`, `NEXTAUTH_URL`.
- **Сделать:** выпустить сертификат (Let's Encrypt после поднятия `budget.fo.az`, либо внутренний CA PASHA), раскомментировать 443-блок + перенести 5 `/api`-auth-блоков, включить redirect 80→443, обновить `NEXTAUTH_URL`.
- **Готово когда:** `https://<host>` с валидным сертификатом, HTTP редиректит на HTTPS.
- **Зависимость:** требует резолва домена/сертификата — может идти параллельно остальным.

### P1-2. Убрать кашу из языков (i18n-согласованность)  · **M**
- **Проблема:** на «Companies» верх по-английски, низ по-русски («Настройки компаний») — на одном экране; сабменю бюджета только по-английски; тултип темы «Toggle theme» не переведён; на логине нет выбора языка.
- **Где:** `src/app/(dashboard)/budgeting/admin/companies/page.tsx` (захардкоженные RU-строки), `src/components/sidebar.tsx` (`budgetSubNav` — захардкоженные label'ы), `src/components/header.tsx:33` (`title="Toggle theme"`), страница логина, `messages/{en,ru,az}.json`.
- **Сделать:** все видимые строки → через `useTranslations`/ключи в `messages/*`; добавить переключатель языка на логин.
- **Готово когда:** на любом выбранном языке нет вкраплений другого; логин переключается EN/RU/AZ.

### P1-3. Человекочитаемые названия отраслей вместо сырых enum  · **S**
- **Проблема:** в UI видны `FOOD_PROCESSING`, `AGRO_CROPS`, `agro_crops`; на «Companies» одна отрасль показана и «Agro / Crops», и «agro_crops» одновременно.
- **Где:** карта меток в `src/lib/industries/data.ts`; потребители — `companies/page.tsx`, `onboarding/page.tsx`.
- **Сделать:** единый `industryLabel(code, locale)` → «Food Processing» / «Пищепром» / и т.д.; заменить все сырые выводы enum.
- **Готово когда:** ни на одном экране нет `SNAKE_CASE`-отраслей; один формат на весь экран.

## Волна P3 — мобильная адаптивность (цель: 3–5 дней, самая крупная) · **L**

### P3-1. Адаптивный сайдбар
- **Проблема:** на телефоне сайдбар не сворачивается, перекрывает контент, страницы режутся («+ Cre…»).
- **Где:** `src/components/sidebar.tsx`, layout `src/app/(dashboard)/layout.tsx`.
- **Сделать:** off-canvas + кнопка-гамбургер, overlay, авто-сворачивание < 768px, закрытие по выбору пункта.
- **Готово когда:** на 375px контент не обрезан, сайдбар вызывается/прячется. **Визуальный гейт + BASELINE UPDATE.**

### P3-2. Рабочие экраны на телефоне (Budgeting / Onboarding / AI Import / Admin)
- **Сделать:** таблицы → горизонтальный скролл/карточки; кнопки и поля не обрезаются; адекватные отступы.
- **Готово когда:** базовые сценарии (создать план, загрузить xlsx, открыть компанию) проходимы на 375px.

### P3-3. Risk Terminal на телефоне — честное состояние, а не сломанные панели
- **Сделать:** на узком экране показывать аккуратный full-screen экран «Терминал лучше открыть на широком экране» (+ ссылки на дружелюбные разделы), без наезжающих панелей.
- **Готово когда:** на 375px нет визуального мусора; есть понятный выход к рабочим разделам. **Визуальный гейт.**

## Волна P4 — доступность и ориентирование (цель: 2 дня)

### P4-1. Поднять нижний предел размера шрифта  · **M**
- **Проблема:** заголовки групп меню 9px, масса текста < 11px (в терминале 518 элементов).
- **Сделать:** минимум ~12px для текста интерфейса; в терминале — отдельный «читаемый» режим/масштаб.
- **Готово когда:** нет тела текста < 12px вне намеренно-плотных зон. **Визуальный гейт.**

### P4-2. Подписи и aria для иконок-действий  · **S**
- **Где:** `header.tsx` (выход, тема), `sidebar.tsx` (сворачивание).
- **Сделать:** видимые подписи или явные `aria-label`; выход — текст «Выйти» рядом с иконкой.
- **Готово когда:** все действия читаются без догадок; скринридер называет их.

### P4-3. Заголовки страниц (h1) + «где я»  · **S/M**
- **Проблема:** у Risk Terminal и ряда экранов нет h1; нет хлебных крошек при 35 экранах.
- **Сделать:** h1 на каждый экран; лёгкие breadcrumbs/заголовок в шапке.
- **Готово когда:** на каждом экране есть заголовок; видно текущий раздел.

### P4-4. Самопомощь на логине  · **S**
- **Сделать:** «Забыли пароль?» (или контакт админа) + контакт поддержки.
- **Готово когда:** заблокированный пользователь видит, куда обратиться.

## Рекомендованная последовательность
1. **Сегодня:** P0-1, P0-2, P0-3 (малые, чинят базовый сценарий новичка) — один день, сразу на прод.
2. **Параллельно:** запустить P1-1 (HTTPS) — зависит от домена/сертификата.
3. **Неделя 1:** P1-2, P1-3, P2-1, P2-2 (язык + жаргон — прямое попадание в «нетехнического»).
4. **Неделя 2:** P3 (мобайл) — самый крупный блок, под визуальным гейтом.
5. **Затем:** P4 (доступность/полировка).

## Оценка
- P0: ~1 день · P1: ~2–3 дня · P2: ~2 дня · P3: ~3–5 дней · P4: ~2 дня.
- Итого ориентир: **2–3 недели** до состояния «новичок проходит ключевые сценарии без помощи».
