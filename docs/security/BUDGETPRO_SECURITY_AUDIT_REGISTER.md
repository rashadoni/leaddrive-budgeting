# BudgetPro — реестр пошагового аудита безопасности

**Стандарт:** [SECURITY_AUDIT_STANDARD.ru.md](SECURITY_AUDIT_STANDARD.ru.md)  
**Создан:** 2026-07-21  
**Режим:** один контроль → отчёт → решение Rashad → исправление/повторная
проверка → отдельное разрешение на следующий контроль.

## Известный контекст, который предстоит перепроверить

Старые документы и roadmap утверждают, что в проекте уже есть глобальный
auth-gate, серверные role/org checks, PostgreSQL RLS, частичный app rate limit,
рекомендация nginx rate limit, secret scanner и ротация production credentials.
Это **исходные гипотезы**, а не автоматически принятый результат нового аудита.

Известные незакрытые сигналы:

- production работает по HTTP; cookie ранее наблюдалась с `Secure=false`;
- применение nginx auth rate limit на реальном edge ещё надо доказать;
- approved vault handoff и break-glass доступ отмечены как незавершённые;
- app limiter описан как in-memory и процесс-локальный;
- MFA и проверка скомпрометированных паролей пока не доказаны.

## Правило изменения реестра

В один момент только одна строка A01–A12 может иметь `IN_PROGRESS`. После
публикации отчёта строка получает фактический статус, но следующая остаётся
`NOT_TESTED`, пока владелец явно не разрешит её начать. Исправления отражаются в
том же отчёте через секцию повторной проверки, а не маскируют первоначальную
находку.

## Ближайший контроль

**A01 — Brute force входа.** До его начала нужно разрешение владельца только на
read-only анализ кода/конфигурации и безопасные тесты на локальном или staging
контуре. Нагрузочные и production-проверки в это разрешение не входят.

**Пауза 2026-07-21:** статическая проверка начата, но итоговый отчёт и
динамическое воспроизведение не завершены; владелец отложил аудит ради основной
работы. Найденный предварительный сигнал не считается закрытой находкой до
выпуска отчёта A01. A02 не начинался.
