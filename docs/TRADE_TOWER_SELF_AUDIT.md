# Trade Tower — самоаудит глазами трейд-маркетолога

*2026-07-07. Роль: директор по трейд-маркетингу дистрибьютора FMCG, 15 лет в отрасли
(P&G/PepsiCo-школа), ежедневно управляет бюджетом 3-6% от оборота. Открывает Trade Tower
впервые. Ниже — его честная реакция, без скидок на то, что модулю неделя.*

---

## Часть 1. Что скажет реальный пользователь

### 1.1 «Это дашборд финансиста, а не трейд-маркетолога» — КРИТИЧНО

Я мыслю **каналами, сетями и SKU**: «Bravo жрёт бюджет?», «что происходит в
традиционной рознице Гянджи?», «какой процент скидки едет на Pepsi 1.5L?».
Trade Tower показывает **одну цифру на всю компанию**. Справочники (12 точек,
10 SKU, каналы, регионы) загружены и — не используются НИГДЕ: ни в бюджете,
ни в журнале, ни в pacing. Название «Control Tower» обещает вид сверху на всё
поле; сейчас это вид на один котёл.

**Вердикт:** канальный разрез — не «улучшение», а порог входа в профессию.
Без него продукт живёт до первого вопроса «а по каналам можно?»

### 1.2 «Карточка кампании — визитка, а не инструмент» — КРИТИЧНО

Проводки журнала УЖЕ умеют привязываться к кампании (`campaignId`), но карточка
не показывает ни **сколько кампания съела**, ни **сколько осталось**, ни бейдж
перерасхода. Первые три вопроса владельца кампании: spent? remaining? on
track? Карточка отвечает только «сколько планировали». Обещанный в ТЗ ROI
далеко (нужен фид продаж), но spent/remaining — это данные, которые уже лежат
в базе и просто не собраны.

### 1.3 «У вас два „плана" — где правда?» — ВЫСОКО

Есть бюджет-пулы (top-down) и есть проводки kind=plan в журнале. Финансовый
директор спросит: какая цифра — обязательства? В TPM-практике это решается
**каскадом**: Budget → Committed (план-проводки/кампании) → Accrued → Actual →
**Available**. Все пять цифр уже в базе — их нужно выстроить в одну линию на
видном месте. Сейчас пользователь должен вычитать в уме.

### 1.4 «Я могу провести затрату в закрытый месяц» — ВЫСОКО (доверие финансов)

Платформа умеет period locks (CFO закрывает месяц), но trade-журнал их
игнорирует. Один тихий backdated posting в закрытый период — и финансы
перестают верить всем цифрам модуля. Это дешёвая защита с готовой инфраструктурой.

### 1.5 «WATCH каждый день = через неделю никто не смотрит на чипы» — ВЫСОКО

Пока нет фида продаж, pace gap сравнивает расход с нулевыми продажами, и статус
честно, но бессмысленно горит WATCH. Alarm fatigue — убийца №1 таких систем:
чип, который всегда жёлтый, равен чипу, которого нет. Алерты мы уже подавили,
а статус — нет. Непоследовательно.

### 1.6 «Промо-календарь где?» — СРЕДНЕ

Трейд-маркетинг живёт календарём: какие кампании идут в каком канале в каком
месяце, где пересечения, где дыры. Лента кампаний по месяцам — самый узнаваемый
артефакт профессии, и его нет.

### 1.7 «Экспорт в Excel где?» — СРЕДНЕ

Каждое совещание в этой отрасли заканчивается фразой «скинь в Excel». Журнал и
бюджет без кнопки XLSX — незаконченный разговор с финансами.

### 1.8 «Кто узнает об алерте, если страницу не откроют?» — СРЕДНЕ

Inbox пассивен. Смысл «увидеть 15-го числа» — чтобы система догнала человека,
а не наоборот. Утренний email-дайджест критичных алертов (мейлер в платформе
уже есть — approval-notifications) закрывает вопрос.

### 1.9 «Кто провёл эту проводку?» — НИЗКО, но дёшево

`createdBy` пишется в базу и не показывается в UI. Подотчётность = половина
дисциплины бюджета.

### 1.10 Честные ограничения стадии (признаём, не маскируем)

- **Uplift не измеряется** — без дневного фида продаж (9.5) ROI кампаний
  невозможен физически. Правильно, что не рисуем фейковый.
- **Claim/deduction matching** — Phase 2, осознанно.
- **Бюджет не делится по типам затрат** (пул скидок ≠ пул листинга) — после
  ответа A2 от клиента.
- **VAT-конвенция не зафиксирована** (суммы с НДС или без?) — вопрос в письмо
  клиенту, в UI — подпись.
- **Полевым (реps) нужен мобильный вид** — далеко за MVP.

## Часть 3. Что НЕ делаем сейчас (и почему)

- **AI-прогнозы** — принцип «сначала цифры, которым верит финансист» держим
  твёрдо (решение из первой сессии).
- **Пер-SKU бюджеты** — грануляция ниже канала без реальных данных клиента =
  спекуляция; ждём Mikro-файлы.
- **Мобильное приложение / SFA-интеграция** — за горизонтом MVP.
- **Многовалютность** — AZN-only до явного запроса.

# Часть 4. Самоаудит, раунд 2 — «всё, кроме данных» (2026-07-07, вечер)

*Данные-зависимые пробелы (фид продаж, файлы Mikro, канальные планы) исключены по
условию — они известны и ждут клиента. Ниже — что НЕ в порядке в том, что уже
построено. Каждый пункт проверен по коду/проду, не по памяти.*

## R1 — КРИТИЧНО: дашборд врёт после проводки

Проводка затраты НЕ пересчитывает pacing и алерты — снимок обновляется только
кнопкой «Recompute». Провёл 100k → дашборд показывает вчерашнюю картину, пока
не нажмёшь кнопку. Для системы, продающей «правду на 15-е число», это
доверие-убийца №1. Fix: авто-recompute после POST/void в журнале (дёшево —
функция уже есть).

## R2 — КРИТИЧНО: period-lock дырявый

T4 закрыл журнал (проводки/сторно → 423 в закрытый месяц), но derive бюджета,
PATCH пула и PUT аллокаций **не проверяют лок вообще** (проверено grep-ом: 0
вызовов). Финансы закрыли месяц → бюджет месяца всё ещё можно переписать.
Непоследовательность хуже отсутствия: она создаёт ложное чувство защиты.

## R3 — ВЫСОКО: ноль handler-тестов на 15+ роутов

Чистые библиотеки покрыты хорошо (75 тестов), но **ни один trade-роут не имеет
handler-теста** (auth/валидация/happy path) — при том, что в остальной кодовой
базе это стандарт. Вся регрессионная защита модуля сейчас держится на ручных
E2E-прогонах из сессии.

## R4 — ВЫСОКО: T8-дайджест на проде МЁРТВ

На VM нет crontab-строки для trade-digest И `CRON_SECRET` не задан в
.env.production → роут отвечает 503. Фича «система догоняет человека» есть в
коде и отсутствует в реальности. Fix: задать секрет + одна crontab-строка.

## R5 — ВЫСОКО: алерты одноязычные

Заголовки/тексты алертов генерируются на английском, при трёхъязычном UI.
Платформа уже решила эту задачу (AlertEvent: messageKey + params) — trade-алерты
это проигнорировали. Для азербайджанского клиента алерт на английском — минус
доверие.

## R6 — СРЕДНЕ: UX-заусенцы (по скриншотам)

- В узкой ширине цифры каналов слипаются («113,728 6,420» читается как одно
  число), названия каналов обрезаются («Ənənəvi t...»).
- «Sales plan achieved / awaiting daily feed» — текст сталкивается.
- Алерт-бейджа нет на вкладке Dashboard — сидя в «Бюджете», не видно, что
  горят 2 critical.
- Дата в формах пустая по умолчанию (должна быть «сегодня»); void без
  подтверждения; вместо скелетонов — «…»; сырые английские ошибки API в UI.
- Мобильная ширина (375px) не проверялась ни разу.

## R7 — СРЕДНЕ: дублирование запросов

/api/trade/campaigns грузится тремя компонентами независимо (календарь, карточки,
форма журнала), /api/trade/overview — тремя. С табами стало лениво, но внутри
вкладки «Кампании» — двойная загрузка одного и того же.

## R8 — СРЕДНЕ: аудит-дисциплина неполная

Ручные проводки/сторно НЕ пишут AuditEvent (только createdBy/voidedBy в строке).
Для финансового модуля платформы, где «every data point must be traceable»,
это отступление от собственного стандарта.

## R9 — СРЕДНЕ: XLSX-заголовки только английские; e2e на страницу нет
Playwright-инфраструктура в репо есть — trade-страница не покрыта ни одним
сценарием.

## R10 — ПРОЦЕСС (честно про себя)

- **Ни одного Codex-review** на код T1–T9 (только дизайн T9). Протокол проекта
  предполагает review-gate на рискованные диффы — я его пропускал ради темпа.
- **Поздние деплои шли мимо deploy/update-prod.sh** (inline ssh rebuild) — т.е.
  без свежего бэкапа перед каждым накатом. Миграции были аддитивные, но
  дисциплина сломана мной же через день после её создания.
- Разделы гайда §13 без скриншотов.
