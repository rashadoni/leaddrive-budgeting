# Замер локальной LLM против нынешнего Sonnet

Клиент не хочет выпускать финансовые данные за периметр и рассматривает локальную модель. Вопрос «какого размера модели хватит» без замера честного ответа не имеет: качество упирается не в число параметров, а в дисциплину следования правилам промпта и в понимание азербайджанских заголовков.

Стенд прогоняет **реальные книги** через продовый код классификатора и даёт две цифры: расхождение классификаций и время на книгу.

## Почему сравнение честное

Используется тот же код, что и в проде — `extractWorkbookMeta` + `classifySheets`, тот же системный промпт, тот же парсер, та же предклассификация без LLM. Меняется только транспорт: `src/lib/llm/openai-compatible.ts` подставляет локальную модель под тот же утиный интерфейс, который ждёт классификатор.

## Что меряем

| метрика | почему важна |
|---|---|
| совпадение типа листа | ошибка → лист уедет не в тот парсер |
| совпадение юрлица | ошибка → деньги запишутся не той компании |
| время на книгу | импорт обязан уложиться в таймаут nginx (300 с) |

Числа модель не считает — их читает детерминированный код адаптеров. Поэтому ошибка модели даёт неверный маршрут, а не тихо испорченную цифру, и ловится на превью.

## Запуск

База — как сегодня в проде:

```
npx tsx scripts/llm-bakeoff/classify-bakeoff.ts \
  --files "data/budget azersheker" --provider anthropic --out /tmp/base.json
```

Кандидат — локальная модель. Ollama, llama.cpp `--api-server` и vLLM говорят одним диалектом:

```
npx tsx scripts/llm-bakeoff/classify-bakeoff.ts \
  --files "data/budget azersheker" --provider openai \
  --base-url http://192.168.1.50:11434/v1 \
  --model qwen2.5:32b-instruct-q4_K_M \
  --out /tmp/qwen32.json
```

Сравнение:

```
npx tsx scripts/llm-bakeoff/compare.ts /tmp/base.json /tmp/qwen32.json
```

## Что нужно, чтобы прогнать

**Для базы** — рабочий `ANTHROPIC_API_KEY` в `.env`. Ключ в локальном `.env` на dev-боксе на 2026-08-24 мёртв (`credit balance is too low`): прод использует другой, платформенный. Без замены базовый прогон падает на каждой книге.

**Для кандидатов** — машина с моделью. На dev-боксе нет ни GPU, ни движка. Ориентиры по памяти в 4-битном кванте: 32B ≈ 19 ГБ весов, 72B ≈ 42 ГБ, плюс KV-кэш под длинные промпты классификатора.

## Как читать результат

Расхождение по типу листа в пределах пары процентов — кандидат годится, ошибки ловятся на превью. Расхождения по юрлицу опаснее: они молча уводят суммы не в ту компанию, тут планка выше.

Если худшая книга у кандидата превышает 300 с, стенд отдельно это подсветит — значит в проде импорт оборвётся по таймауту прокси, каким бы хорошим ни было качество.
